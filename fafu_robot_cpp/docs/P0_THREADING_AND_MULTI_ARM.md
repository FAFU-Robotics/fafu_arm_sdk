# P0 线程与多机械臂约定

Python SDK 和原生 C++ SDK 共享 `fafu::core::RobotCore`，避免两套状态机、
使能恢复和 Servo 安全策略逐渐分叉。

## 单个 SDK 实例

- 状态、健康信息和缓存读取允许多线程并发。
- 同一时刻只允许一个写控制操作；冲突立即抛出 `BusyError`，不会交错发送
  `move_j`、Servo、抓取或重力补偿帧。
- 同线程的组合动作可以嵌套，例如 `go_home -> move_j`。
- Servo 会话归启动它的线程所有；`servo_j` 和正常 `servo_end` 必须由该线程调用。
- `emergency_stop` 可以从其他线程调用；它先锁存取消，再通过实例内命令门禁
  发送 STOP，保证竞态中的普通控制帧先完成、STOP 最后发送。
- `close_connection` 会请求取消并等待正在执行的写操作退出；超时会报错，不会
  一边关闭串口一边继续发送。
- `close_connection` 和底层 `close` 都是幂等的。

底层 `driver()` / Python `_ht` 是高级逃生口。它的缓存、发送和生命周期分别有
必要的锁，但绕过 `RobotCore` 直接并发发送控制命令不属于高层线程安全保证。

## 多个 SDK 与多个进程

- 每个 SDK 实例拥有独立状态、锁、缓存、线程和故障锁存；一台机械臂进入
  `DEAD` 不会污染另一台机械臂。
- 多机械臂必须显式配置不同串口。`auto` 只有在恰好发现一个调试板时才成功；
  发现多个端口会要求调用方明确选择，避免控制错机械臂。
- Windows 串口保持系统级独占打开。
- Linux 使用非阻塞 `flock` 对 TTY 做进程级独占。同一个串口被第二个程序打开
  时会立即报错；不同串口上的两个 Python/C++ SDK 可以独立运行。
- 串口库静态链接到扩展和原生 SDK，不再依赖工作目录中的平台 DLL/SO。

## 仍由多机械臂上层负责

P0 不引入全局协调器，以下策略需要由工作站或应用层统一实施：

- 两条机械臂之间以及与环境之间的碰撞检查；
- 共享工作区、夹具和工件的互锁；
- 共用电源、急停回路和故障复位顺序；
- 多机械臂同步动作的时间戳、屏障和超时；
- 串口与机械臂序列号/物理标签的持久映射；
- 单臂故障后其他机械臂应继续、保持、刹车还是全部急停。

这样保留了 SDK 的小而明确的职责：保证单臂实例不交错写、故障隔离、端口不被
重复占用；跨机械臂业务安全不被隐藏在串口驱动里。
